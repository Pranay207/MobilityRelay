## Bugs Reproduced and Fixed

1. **Private storage served by development middleware.** A synthetic canary in
   `.data` was accessible without authenticating to the protected API. Vite now
   denies private storage, the configured data directory, environment files,
   credential directories and certificate/key files. Its cache lives under
   `node_modules/.vite`, not alongside case data. Public-directory serving is
   disabled in development middleware. Regression checks cover direct, encoded,
   query-suffixed and `@fs` requests. This was an application configuration
   omission, not a demonstrated Vite vulnerability.
2. **Incorrect JSON error status.** Invalid or oversized JSON produced generic
   server errors. Responses are now 400 and 413, with no parser payload echoed.
3. **Broken IPv6 internal MCP origin.** `HOST=localhost`/`::1` could bind IPv6 while
   the internal client attempted IPv4. The origin now follows the actual bound
   loopback address. Both bindings pass real HTTP-to-MCP reads.
4. **Unsafe or inconsistent configuration.** HTTPS public origins are normalized
   and reject credentials, paths, queries and fragments. Storage cannot be the
   app root or inside `public`, `dist` or `node_modules`.
5. **Missing deletion-body validation.** Absent confirmation could cause a 500.
   Missing, incorrect and extra fields now return 400 without deleting the case.
6. **Dialog focus leaves the popup.** Native Edge dialog behavior reached the
   document body when tabbing beyond the final control. Explicit forward/reverse
   focus wrapping now keeps focus inside. Escape closes and restores trigger
   focus. The test exercises 18 Tab and 18 Shift+Tab presses on both viewports.
7. **Insufficient text contrast.** Pale secondary labels and populated user
   messages failed automated contrast checks. Scoped colors now pass the tested
   views. Superseded evidence remains readable rather than faded with opacity.
8. **Narrow-screen overflow.** Long category/person/equipment/source strings and
   a long topbar reference overflowed at 320 pixels. Wrapping and constrained
   header flex tracks fix the reproduced cases without hiding page overflow.
9. **Assistant export could disable redaction.** Two provider regression tests
   reproduced a model requesting `redact:false` while its reply claimed redaction.
   The host now always enables redaction for assistant exports. Reviewed manual
   exports retain their explicit option; redaction is not complete anonymization.
10. **Intermittent HTTP stalls/socket failures.** A live-AI rerun timed out, and a
    later concurrent read test reproduced a stall. Internal MCP clients now have
    separate, explicitly destroyed Undici dispatchers, no pipelining, and a
    30-second total HTTP deadline combined with the SDK cancellation signal.
    Two stalled-server tests verify cancellation, no replay and no success trace.
    Further raw TCP checks showed Node advertising content length in its local
    response metadata while the received wire header advertised chunking without
    matching body chunks. All MCP responses now use consistent native chunk
    framing via an `on-headers` hook, including optional GET/405 and auth/error
    responses. Six wire paths and the full backend suite pass. The source of the
    observed header normalization is not established; no vendor defect is claimed.
11. **Read replies blocked behind a redundant refresh.** Browser traces showed a
    completed case-brief API call, then an extra case reload stalling while the
    interface remained busy. Read-only replies now reload conversation history
    without rereading unchanged case data. Writes and review proposals still
    refresh the case, and periodic synchronization remains. Two new browser
    regressions and both speech-playback checks pass with unchanged five-second
    assertions in the focused run.

Docker build-context exclusions were additionally expanded for credential/tool
directories and database/message files. No image build was claimed.

## Live AI Observations

Actual Ollama server version was 0.40.4; the model was `qwen2.5:1.5b`. The final
full run took 22.3 seconds for a read explanation, 31.5 seconds to prepare the
draft, 0.3-0.4 seconds each for delivery-status/send-boundary responses and the
record-review proposal, and 21.4 seconds for redacted HTML export.
The separate real browser draft took 15.6 seconds. Earlier passing runs reached
46.8-55.3 seconds for explanations/drafts and 40.9 seconds for export. These are isolated CPU-host
observations, not a speed guarantee. No automatic fallback or outbound email was
used. The six-step check requires persisted MCP results, correct recipient/topic,
approval boundaries and real redacted file content.

An earlier run returned valid JSON but failed an HTML-only verifier assumption.
The verifier now checks either supported file format, its actual content and
known-identity redaction. A second run timed out before the shared HTTP-client
hardening. The final full run and browser check pass; those earlier failures are
not erased and repeated long-run reliability is not established.

The read answer still uses generated prose. An earlier statement that paperwork will
allow authorization must not be treated as a coverage prediction or proof of
submission. Source reports remain user-maintained and the insurer's decision
cannot be inferred from a receipt reference. Free-form read accuracy and
calibration remain open quality concerns even when the action tests pass.

## Coverage and Timing

Backend coverage includes all six MCP tools, protocol negotiation `2025-11-25`,
discovery, bearer/Host/Origin checks, sessions, CSRF, login throttling, logout,
cross-case IDs, idempotency, corrected evidence, exact-message approval,
expiration/replay/concurrent sends, uncertain delivery, redacted/escaped export,
whole-case deletion, persistence and interrupted sends.

The internal client deadline tests also check the actual timeout error and one
unanswered HTTP request, rather than accepting any rejection as success.

Agent tests use controlled provider responses to exercise bounded context,
restricted tools, scoped references, prompt-injection-like action attempts,
unsupported claims, malformed/truncated responses and provider failures. These
are safety regressions, not a general accuracy evaluation of either model.

Browser coverage exercises the full case lifecycle, real MCP traces, source
comparison and corrections, review gates, failed-request input recovery,
case-switch isolation, timezone edits, microphone-denial fallback and cancelled
speech callbacks. Speech recognition/synthesis APIs are controlled substitutes.

A small concurrent read check completed 25 HTTP-to-MCP brief requests in five
batches of five, with unchanged case state. Final observed median was **346 ms**,
p95 **489 ms**, on this Windows host during the backend suite. Each request includes
SDK initialization, discovery and a tool call. These are not standalone tool
timings, native Alexa's latency measurement, a sustained load test, or a
production capacity guarantee.

Early runs contained real layout/contrast failures, initial case-load timeouts,
and read replies waiting behind a stalled redundant refresh. One 34-test run
was stopped to investigate framing after it reproduced a failure; it is not
counted as a passing run. The complete final rerun passed with the existing
timeouts and no retries. A mobile long-field test also used an incorrect exact
`Requests` selector when the visible tab included a count; that test bug was
fixed. Mobile width assertions now compare against the actual configured
viewport, not an `innerWidth` inflated by overflow. An invalid overlength fixture
and a duplicate-alert selector were corrected without weakening application
validation.

Private-file denial messages are expected in the security test. Occasionally
closing its short-lived Vite instance interrupts dependency pre-scanning and
prints a shutdown diagnostic; the final browser app still renders and passes.
Node also warns that its built-in SQLite API is experimental.

The framing investigation deliberately kept a fixed-length experiment red when
wire parsing failed, then verified Node-generated chunk boundaries on raw TCP.
The final hook applies to every MCP response path rather than only successful
tool results. HTTP JSON responses and an optional GET returning 405 are permitted
by the [Streamable HTTP specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

## Still Not Verified

- Physical microphone recognition, audible responses and screen-reader use.
- Firefox, Safari, actual mobile hardware or a second operating system.
- Live SMTP delivery/receipt, live Bedrock, native Alexa+ onboarding/account
  linking, public deployment or TLS/reverse-proxy operation.
- Docker image build, persistent volume permissions or container health checks.
- Sustained/adversarial load, penetration testing, encrypted clinical storage or
  multi-user isolation. This remains a shared-workspace prototype.
- User benefit, time savings, shortened wheelchair repairs or judging outcomes.

Automated scans do not certify full WCAG conformance. Human accessibility and
user testing remain necessary. [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing)
and [Vite file-denial behavior](https://vite.dev/config/server-options#server-fs-deny)
describe the underlying tools and limitations.

The owned-dispatcher approach uses the documented
[Node fetch dispatcher option](https://nodejs.org/docs/latest/api/globals.html#fetch)
and [Undici Agent cleanup](https://github.com/nodejs/undici/blob/main/docs/docs/api/Agent.md),
without changing the global HTTP dispatcher or adding retry middleware.
